# Keputusan teknis

- **Next.js 15 + React 19 + Tailwind 3, npm.** Versi dipin agar build reprodusibel; `package-lock.json` ikut di-commit.
- **Route handler Node, bukan edge.** Streaming dan `AbortController` sama-sama didukung, tetapi Node memberi batas waktu function yang eksplisit (`maxDuration`) dan tidak menambah batas ukuran respons edge. Tidak ada keuntungan edge untuk satu pengguna.
- **`maxDuration = 300`, bukan 60.** Dengan Fluid Compute (default) Hobby mengizinkan 300 detik; 60 detik adalah batas lama sebelum Fluid Compute. Batas atas tetap dijaga `timeoutMs`/`idleTimeoutMs` per model, jadi angka ini hanya mencegah jawaban panjang terpotong.
- **Browser ↔ Vercel memakai NDJSON, bukan SSE.** Satu JSON per baris tidak bisa di-buffer sebagian proxy dan parser-nya ±20 baris, sementara Worker tetap memakai kontrak SSE/JSON yang sudah ditentukan.
- **Registry model tetap di server; client menerima field tampilan lewat props RSC.** Ini menjaga nama env dan konfigurasi Worker tidak masuk bundle, tanpa memecah registry jadi dua file.
- **zod hanya di server dan dimuat dinamis untuk validasi impor.** Client memakai type guard kecil untuk event stream agar bundel awal tidak bertambah ±13 KB.
- **Shiki core + JavaScript regex engine + impor bahasa per-blok.** Tidak ada WASM yang perlu diunduh/diizinkan CSP; tema `github-light`/`github-dark` di-tokenisasi sekaligus sehingga toggle tema hanya mengganti CSS variable, bukan mengulang highlight.
- **CSP nonce via middleware + `force-dynamic`.** Halaman statis tidak bisa memakai nonce per-request; aplikasi ini tidak butuh caching HTML.
- **Tanpa Vercel AI SDK.** Kontrak Worker ditentukan pemilik; yang dibutuhkan hanya `fetch` + parser, dan SDK akan menambah lapisan serta asumsi format.
- **Konteks dipangkas dari pesan terlama, bukan memotong satu pesan.** Pesan terakhir selalu dikirim utuh agar tempelan besar tetap sampai; jumlah yang dibuang diberitahukan di atas input.
- **"Lanjutkan" menambahkan teks ke pesan asisten yang sama** dengan instruksi user tambahan, agar riwayat tidak dipenuhi pesan palsu.
- **Lampiran jadi blok kode berlabel**: satu baris nama file dalam inline code diikuti fenced block. Format ini tetap terbaca sebagai teks biasa dan tidak merusak isi kode saat disalin.
- **`<dialog>` native dan `window.confirm`** untuk system prompt dan hapus percakapan; keduanya sudah menangani fokus, Esc, dan pembaca layar tanpa dependensi UI.
- **Rate limit login di memori proses.** Cukup untuk satu instance dan memperlambat tebing password; batas ini didokumentasikan di README, bukan dianggap global.
- **Framing ditolak secara default, dengan opt-in `ALLOW_IFRAME_EMBED=1`** untuk panel preview yang menempelkan app dalam iframe; opsi ini tidak dipakai di produksi.
- **`img-src` tidak mengizinkan domain luar**, sehingga gambar dari internet di dalam markdown tidak dimuat (pilihan sadar untuk privasi).
- **Fallback hanya sebelum token pertama dan selalu ditampilkan.** Menyembunyikan perpindahan model akan menyesatkan saat membandingkan kualitas jawaban.
- **Timeout diuji dengan entri registry sementara** (`probe-test`, `timeoutMs: 1500`, `idleTimeoutMs: 1200`) yang dihapus setelah verifikasi; ini sekaligus membuktikan penambahan model hanya butuh satu entri + satu env var.
- **Nama model kustom adalah override per percakapan, bukan entri registry baru.** Entri `MODELS` diperlakukan sebagai penyedia (Worker + URL + token); field `customModel` opsional di body `/api/chat` menggantikan `upstreamModel` sebagai `model`. Ini memungkinkan mencoba nama model baru tanpa mengubah `src/config/models.ts` dan tanpa redeploy, sementara daftar penyedia dan kredensialnya tetap hanya di server.
- **Override tidak berlaku untuk fallback.** Nama kustom milik katalog penyedia primer dan belum tentu ada di penyedia fallback; mengirimkannya ke fallback akan mengubah percobaan pemulihan menjadi error 4xx yang tidak informatif. `effectiveUpstreamModel()` karena itu mengabaikan `customModel` saat `isFallback`, dan label balasan menampilkan nama model fallback yang benar-benar dipakai.
- **Override hanya untuk format `openai`.** Hanya format itu yang membaca field `model`; `sse-text`/`json-text` mengabaikannya, jadi UI menonaktifkan input lewat `supportsCustomModel` daripada menawarkan kontrol yang tidak berefek.
- **Field `customModel`/`modelName` opsional di skema impor dan storage.** Percakapan lama dan file ekspor sebelum fitur ini harus tetap terbuka; validasi nama memakai regex yang sama di client, zod server, dan skema impor (satu sumber di `src/lib/model-name.ts`).
- **Saran nama model di IndexedDB, terpisah dari percakapan.** Daftar saran bersifat global per penyedia (bukan per percakapan) agar bisa dipakai ulang cepat; kegagalan IndexedDB (private mode) ditelan dan tidak menghalangi penyimpanan percakapan.
- **Penanda file `<file name="…" lang="…">…</file>`, bukan blok kode.** Tag ini tidak lazim di dalam kode (yang sering memuat `` atau `<div>`), sehingga tidak bentrok seperti penanda "``file". Atribut dibaca longgar (`name`/`file`/`title`, `lang`/`language`), nama selalu disanitasi sebelum dipakai untuk unduhan, dan parser mengabaikan tag mirip (`<files>`, `<filename>`) maupun tag yang ditulis di dalam blok berpagar sebagai contoh dokumentasi.
- **Parser berjalan saat render, bukan saat menyimpan.** File dibangun dari teks pesan tiap render (`src/lib/file-blocks.ts`), jadi tidak ada perubahan skema penyimpanan, ekspor, atau impor; percakapan lama tetap sah. Hasil parse di-cache per id pesan dengan pemeriksaan identitas string agar tiap token tidak memicu parse ulang seluruh percakapan.
- **Tag yang belum tertutup tetap jadi file.** Saat streaming, potongan tag ditahan dari bubble dan isi yang sudah masuk tampil live dengan penanda "menulis…". Bila stream di-Stop, file yang belum tertutup tetap tampil sebagai "belum selesai" — lebih jujur daripada membuang isi yang sudah diterima.
- **Blok kode berpagar > 30 baris juga menjadi file.** Sebagai fallback untuk model yang mengabaikan konvensi tag; nama dan bahasa diambil dari info string, dan nama sintetis dipakai bila tidak ada. Konsekuensinya blok kode panjang tidak lagi tampil inline — diterima agar perilaku konsisten untuk semua model.
- **Versi file dikelompokkan per nama, bukan per pesan.** Revisi dengan nama yang sama menjadi `v1`, `v2`, … dengan versi terbaru terpilih otomatis; pengguna dapat memilih versi lama lewat dropdown. Tidak ada data versi tambahan yang disimpan.
- **Status panel disimpan di IndexedDB terpisah (`ai-gateway:file-panel:v1`).** "Panel terbuka dan tab aktif diingat per percakapan" tidak boleh mengubah skema percakapan/ekspor, jadi status UI disimpan sebagai peta `conversationId → {open, name}` dengan sanitasi dan batas 80 entri; kegagalan IndexedDB ditelan.
- **CSP tidak diubah sama sekali.** Pratinjau memakai `<iframe sandbox srcdoc>`, dan `frame-src` tidak mengatur `srcdoc` karena bukan permintaan jaringan (CSP3 memperlakukan `about:srcdoc` sebagai dokumen yang mewarisi kebijakan induk). Jadi `frame-src 'none'` tetap berlaku untuk frame berbasis URL, sementara pratinjau dikunci oleh atribut `sandbox` dan CSP di dalam dokumennya sendiri. Melonggarkan `frame-src` hanya akan menambah permukaan serangan tanpa manfaat. Bila suatu saat browser menolak `about:srcdoc` lewat `frame-src`, satu-satunya perubahan yang diperlukan adalah `frame-src 'self'` — dicatat di sini supaya tidak "diperbaiki" dengan `frame-src *`.
- **Pratinjau memakai `<iframe sandbox="">` plus CSP di dalam dokumen.** Sandbox tanpa `allow-same-origin`/`allow-scripts` membuat dokumen beropini origin buram: tidak bisa membaca cookie, localStorage, atau DOM induk, dan skrip tidak berjalan. CSP `default-src 'none'` di dalam `srcdoc` menutup akses jaringan (gambar/font/stylesheet/fetch eksternal), sehingga pratinjau aman meski isinya HTML buatan model.
- **Isi file selalu teks di halaman utama.** Hanya panel yang merender `.md` (lewat react-markdown, `skipHtml`) atau HTML/SVG (lewat iframe terpisah); bubble hanya menampilkan kartu, jadi tidak ada jalur HTML mentah ke dokumen utama.
